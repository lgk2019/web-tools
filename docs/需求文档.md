## 一、项目概述

### 1.1 项目背景

在日常办公与开发场景中，用户经常需要对图片、PDF、文本等文件进行轻量级处理（如压缩、裁剪、去水印、格式转换等）。市面上的工具多为分散的单一功能网站，用户需在多个站点间切换，体验割裂且存在隐私泄露风险（文件上传至第三方服务器）。

本项目旨在打造一个**一站式、纯前端优先、隐私安全**的在线工具箱，将高频小工具聚合到统一站点，提升使用效率并保障数据安全。

### 1.2 项目目标

| 目标维度 | 描述 |
|---------|------|
| 功能目标 | 提供图片、PDF、文本、二维码等不少于 10 个高频小工具 |
| 性能目标 | 首屏加载 ≤ 2s；纯前端工具处理响应 ≤ 1s |
| 隐私目标 | 可前端完成的处理一律不上传服务器，文件处理完即销毁 |
| 体验目标 | 统一设计语言，零学习成本，支持移动端自适应 |
| 扩展目标 | 工具模块化，新增工具仅需注册配置，无需改动核心框架 |

### 1.3 用户群体

- **办公人员**：日常处理文档、图片、PDF 的白领用户
- **设计/运营人员**：需要批量处理图片素材的从业者
- **开发者**：需要格式转换、编码解码、二维码等技术工具的开发者
- **普通用户**：偶尔需要处理文件的互联网用户

## 二、核心功能模块

本平台工具按处理对象分为五大类。其中标注「🟢前端」表示纯浏览器端处理，「🟡后端」表示需调用 FastAPI 后端，「🔵混合」表示前端处理 + 后端增强。

### 2.1 图片处理类

#### 2.1.1 图片压缩 🟢
- **输入**：JPG / PNG / WebP / GIF，支持单张或批量（≤ 20 张）
- **功能**：
  - 自定义压缩质量（1-100 滑块）
  - 自定义输出尺寸（按比例 / 按像素）
  - 输出格式转换（如 PNG → WebP）
  - 压缩前后体积对比、预览效果
  - 批量压缩后打包下载（ZIP）
- **技术方案**：Canvas + `toBlob` API，批量打包使用 `jszip`
- **限制**：单文件 ≤ 20MB

#### 2.1.2 图片去水印 🟡
- **输入**：含水印的图片
- **功能**：
  - 矩形框选水印区域
  - 涂抹笔刷手动擦除（可选笔刷大小）
  - 自动检测水印（AI 模型，进阶功能）
  - 处理后预览 + 下载
- **技术方案**：
  - 简单场景：Canvas 区域采样 + Inpaint 算法（前端）
  - 复杂场景：调用 FastAPI 后端，集成 OpenCV / 预训练模型
- **限制**：复杂背景去除效果有限，需提示用户

#### 2.1.3 图片裁剪 🟢
- **输入**：任意图片
- **功能**：
  - 自由裁剪（拖拽定界框）
  - 预设比例（1:1 / 4:3 / 16:9 / 9:16 等）
  - 旋转、翻转
  - 输出格式选择
- **技术方案**：`react-image-crop` 或自研 Canvas 裁剪组件

#### 2.1.4 图片格式转换 🟢
- **功能**：JPG / PNG / WebP / BMP 互转
- **技术方案**：Canvas 重绘导出

#### 2.1.5 图片拼接 🟢（扩展）
- **功能**：多图横向 / 纵向拼接，可选间距、背景色

### 2.2 PDF 处理类

#### 2.2.1 PDF 文件编辑 🔵
- **输入**：PDF 文件（≤ 50MB）
- **功能**：
  - **页面操作**：合并、拆分、删除页面、页面重排序
  - **内容编辑**：添加文字、添加图片、添加水印
  - **格式转换**：PDF ⇄ 图片（每页转 PNG/JPG）、PDF ⇄ Word（🟡后端）
  - **页面编辑**：旋转页面、压缩 PDF
  - **安全**：PDF 加密、解密、添加密码
- **技术方案**：
  - 前端：`pdf-lib` 进行页面级操作（合并/拆分/旋转/水印）
  - 前端：`pdfjs-dist` 进行渲染与预览
  - 后端：`PyMuPDF` / `pdf2docx` 处理复杂转换

#### 2.2.2 PDF 压缩 🟡
- 通过重新采样图片、降低质量、去除冗余对象实现压缩

### 2.3 二维码工具类

#### 2.3.1 二维码生成器 🟢
- **输入**：文本 / URL / 名片 / WiFi 信息
- **功能**：
  - 自定义尺寸（128-1024px）
  - 自定义颜色（前景色、背景色）
  - 自定义容错等级（L / M / Q / H）
  - 嵌入 Logo（居中图片）
  - 输出格式：PNG / SVG
- **技术方案**：`qrcode` 库生成

#### 2.3.2 二维码识别 🟢（扩展）
- 上传图片识别二维码内容，支持摄像头扫码

### 2.4 文本处理类（扩展）

- **JSON 格式化 / 校验**
- **Base64 编解码**
- **URL 编解码**
- **MD5 / SHA 哈希计算**
- **文本对比（Diff）**
- **颜色格式转换**（HEX / RGB / HSL）

### 2.5 单位换算类（扩展）

- 长度、重量、温度、面积、数据存储等单位换算

### 3.1 整体架构

```

│  └──────┬──────┘  └─────────────┘  └─────────────┘      │
│         │                                                 │
│  ┌──────▼────────────────────────────────────────┐       │
│  │      Canvas / File API / 本地处理              │       │
│  │  (图片压缩、裁剪、二维码、PDF页面操作等)        │       │
│  └──────┬────────────────────────────────────────┘       │
└─────────┼─────────────────────────────────────────────────┘
          │ 仅复杂任务走 HTTP
          ▼
┌─────────────────────────────────────────────────────────┐
│                  FastAPI 后端服务                         │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐          │
```

### 3.2 前端技术栈

| 技术 | 版本 | 用途 |
|------|------|------|
| React | 18.x | UI 框架 |
| Vite | 5.x | 构建工具与开发服务器 |

| 技术 | 用途 |

- 前端：构建为静态资源，部署至 Nginx / Vercel / CDN

- 存储：文件处理为临时性，不持久化；使用内存或 `/tmp` 目录，处理完即清理
- HTTPS：全站强制 HTTPS

## 五、接口设计（后端 API）

仅列出需要后端处理的接口，纯前端工具无接口。

### 5.1 通用约定

- Base URL：`/api/v1`
- 请求：`multipart/form-data`（文件上传）或 `application/json`
- 响应：统一 JSON 格式

```json
{
  "code": 0,
  "message": "success",
  "data": { ... }
}
```

### 5.2 接口列表

| 方法 | 路径 | 功能 | 入参 | 出参 |
|------|------|------|------|------|
| POST | `/api/v1/image/remove-watermark` | 图片去水印 | file, regions (JSON) | 处理后图片 URL |
| POST | `/api/v1/image/ai-enhance` | AI 图片增强 | file | 增强后图片 |
| POST | `/api/v1/pdf/to-word` | PDF 转 Word | file | .docx 文件流 |
| POST | `/api/v1/pdf/compress` | PDF 压缩 | file, quality | 压缩后 PDF |
| POST | `/api/v1/pdf/ocr` | PDF OCR 识别 | file | 文本内容 |
| GET | `/api/v1/file/:id` | 获取处理结果 | id | 文件流 |

> **说明**：所有上传文件在服务端临时存储，处理完成后 5 分钟内自动删除，不保留任何用户数据。

## 六、非功能性需求

### 6.1 性能
- 首屏 LCP ≤ 2.5s（4G 网络）
- 前端工具处理 5MB 图片 ≤ 1s
- 后端接口响应 ≤ 3s（常规任务）
- 支持懒加载，工具按需加载（路由级 Code Splitting）

### 6.2 安全与隐私
- **数据不落地**：纯前端工具文件不上传；后端处理文件处理完即删
- **无用户系统**：初期不要求登录，无用户数据收集
- **HTTPS**：全站强制 HTTPS
- **文件校验**：上传文件类型与大小校验，防止恶意文件
- **CORS**：后端配置严格跨域策略

### 6.3 兼容性
- 浏览器：Chrome 90+、Firefox 88+、Safari 14+、Edge 90+
- 移动端：iOS Safari 14+、Android Chrome 90+
- 响应式断点：移动端 (<768px)、平板 (768-1024px)、桌面 (>1024px)

### 6.4 可用性
- 支持 PWA，可离线使用纯前端工具
- 支持深色/浅色主题切换
- 支持快捷键操作（常用工具）

### 6.5 SEO
- 每个工具页独立 URL，支持服务端渲染或预渲染
- 结构化数据标记
- sitemap.xml 自动生成

## 九、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 浏览器兼容性导致处理失败 | 中 | 核心功能做特性检测，降级提示 |
| 大文件处理导致页面卡顿 | 高 | 使用 Web Worker 异步处理，进度反馈 |
| 去水印/AI 效果不达预期 | 中 | 明确标注效果限制，提供手动涂抹方案 |
| 后端文件被恶意利用 | 高 | 严格类型校验、频率限制、自动清理 |
| 版权与合规风险 | 中 | 去水印功能添加使用声明，禁止用于侵权用途 |

> 🔒 **隐私优先**：本工具箱中绝大多数处理在你的浏览器本地完成，文件不会上传到任何服务器。需要后端处理的任务会在处理完成后立即删除临时文件，我们不存储任何用户数据。
